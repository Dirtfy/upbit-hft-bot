# paper_trading — 공식 모의투자 기록 (2026-09-25 시작)

오너 미션에 따라 약 1개월간 **모의투자(paper trading)** 기간을 공식 운영하며,
그 기록을 이 디렉터리에 **커밋/푸시**로 축적한다.

## 안전 (변경 없음)
- **실거래 주문 없음, API 키 없음, 계좌 접근 없음.** 공개 시세(read-only)만 사용.
- 가상 자본 **1,000,000 KRW**, 노출 상한 1,000,000 KRW, 모든 리스크 한도 유지.
- 전략 신호는 백테스트와 **동일한 코어**(`src/regime.py` + `src/bear_strategy.py`)를
  그대로 사용 — 기록된 것이 곧 검증된 로직이다.

## 무엇을 기록하나
매 사이클(마감된 일봉 1개 = 1 사이클)마다:

| 파일 | 형식 | 내용 |
|---|---|---|
| `JOURNAL.md` | 사람이 읽는 저널 | 사이클별 장세·신호·행동·**진입/청산 근거**·손익(사이클/누적) |
| `paper_log.jsonl` | 기계 판독 원장 | 위와 동일 정보를 사이클당 JSON 1줄로(누적) |
| `market_data_daily.csv` | 축적 시세 | 그 사이클에 쓴 일봉 OHLC(백테스트용 커밋 데이터셋) |

손익 정의: 판단=마감 일봉, 체결가=해당 봉 종가, 수수료 0.05%/편도, 한 번에 한
포지션. `equity = 현금 + BTC평가액`, 사이클 손익 = 직전 대비 평가액 변화, 누적
손익/수익률 = 시작 1,000,000 KRW 대비.

## 실행
```bash
python3 paper_trading/paper_trader.py            # 기본 모드 long_flat
python3 paper_trading/paper_trader.py --mode breakout_regime
```
**멱등(idempotent):** 마지막으로 기록한 봉 이후의 새 봉만 추가하므로 아무 때나
다시 돌려도 안전하다. 첫 실행은 그 시점의 최신 마감 봉에서 시작(과거 백필 없음 —
앞으로의 전진 기록).

일일 사이클 케이던스(하루 1회)면 일봉 1개/일이 정확히 축적된다.

## 4시간봉(4h) 축적 — 자율 데몬 (오너 지시 2026-09-27, Cycle 24)

일봉 축적은 그대로 두고 4시간봉 축적을 병행한다. **핵심 원칙(오너 지시): 데이터
축적은 리더(Claude) 턴 안에서 수행하지 않는다 — 그건 토큰을 쓴다.** 대신 4h 수집을
**Claude와 완전히 분리된 OS 데몬**이 스스로 돌린다. Claude(리더)는 오너가 명령할
때만 데몬의 산출물(트레일/로그)을 **읽고** 판단·커밋만 한다.

```bash
# 데몬 제어 (리더 턴이 아니라 OS 프로세스로 상주)
paper_trading/daemon_4h.sh start     # 분리(setsid)된 데몬 기동 — 멱등
paper_trading/daemon_4h.sh ensure    # 죽어 있을 때만 재기동(호스트 리부트 자가치유)
paper_trading/daemon_4h.sh status    # 생존/실행시간/최근 로그/트레일 무결성
paper_trading/daemon_4h.sh stop      # 정지
paper_trading/daemon_4h.sh restart   # 재기동
paper_trading/daemon_4h.sh logs      # 데몬 로그 tail
```

**왜 데몬으로 도는가 / 어떻게 항상 살아있나 / 재시작 / 로그 / 멱등 백필**
- **분리 실행(토큰 0)**: `setsid` + `</dev/null`로 기동해 하네스에서 떨어져 나가
  **PID 1(오케스트레이터)로 reparent**된다(검증: `ppid=1`). 리더 턴이 끝나도 계속
  돌고, **Claude 토큰을 전혀 쓰지 않는다.** 호스트는 다일(多日) 상시 가동이라 매
  턴 경계를 넘어 생존한다.
- **크래시 내성**: 루프가 collect_4h.py를 서브셸에서 실행하고, 실패 시 로그만 남기고
  다음 4h 틱으로 계속 간다(한 번의 조회 실패로 죽지 않음). `sleep & wait` 구조라
  stop/restart 시그널도 즉시 반영된다.
- **재시작(자가치유)**: 이 환경엔 시스템 크론/systemd가 없어 **호스트 리부트만이**
  데몬을 멈출 수 있다. `daemon_4h.sh ensure`가 "안 돌고 있을 때만" 재기동하는
  멱등 라이브니스 체크다. 리더는 명령받은 턴 시작 시 이 한 줄만 호출하면 된다
  (축적이 아니라 생존 확인 — 비용 거의 0). 리부트로 생긴 공백은 아래 백필이 메운다.
- **갭 없는 백필(self-healing)**: 매 틱이 "마지막 기록 이후 마감된 모든 4h봉"을
  백필하므로 다운타임/케이던스와 무관하게 완전하다.
- **로그/상태**: `logs/collect_4h_daemon.log`, PID 파일 `logs/collect_4h_daemon.pid`.

**저장/커밋 모델**
- 저장: 커밋되는 전진 축적 트레일 **`market_data_4h.csv`**(time,OHLC,volume).
  전체 9년 4h 원시데이터는 기존 규약대로 gitignore된 `data/krw_btc_4h_full.csv`.
- **무결성**: 매 틱 후 중복·역순·갭(4h 간격)을 검사해 출력(정상 시 모두 0).
- **커밋 분리**: 데몬은 로컬에 **append만** 한다(축적 = 토큰 0). git 커밋·푸시는
  오너가 명령한 리더 턴이 축적된 트레일을 읽고 수행한다 — git 이력을 깔끔히 유지
  (하루 6커밋 방지)하고 데몬↔리더 push 경합을 피한다.

**진짜 4시간 주기를 회사 인프라로 보장하려면(선택, 데몬으로 이미 충분하지만
리부트-후-자동복구까지 원하면):** 상시 호스트에 아래 크론 한 줄. `daemon_4h.sh`가
멱등이라 이 줄만 있으면 리부트 후에도 데몬이 항상 되살아난다.
```cron
*/10 * * * * cd /workspace/upbit-hft-bot/leader && paper_trading/daemon_4h.sh ensure >> logs/collect_4h_daemon.log 2>&1
```
(구식 `run_4h_collector.sh` + `7 */4 * * *`는 단발 실행용 래퍼로 남겨둠 — 데몬이
상위 호환.) 상세는 `report.txt`.

### 4h 모의투자 트랙(선택) — 일봉 원장과 분리
현재 방어 전략의 장세필터는 **일봉 기준(SMA200 등)**이라 4h봉에 그대로 적용하면
의미가 달라진다. 그래서 이번 단계는 **4h 데이터 축적까지만** 수행한다. 4h 기반
모의투자 트랙이 필요하면 4h에 검증된 전략(리서치의 Donchian 30/20)으로 **별도
디렉터리·별도 원장**에 구성하며, 일봉 원장(`paper_log.jsonl`)과 절대 섞지 않는다
(모드 일관성 가드 유지).
